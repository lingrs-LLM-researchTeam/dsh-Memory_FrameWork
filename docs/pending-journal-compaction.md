# 恢复日志正文压缩

范围为单 Host、独立 `instanceId` 的 `dsh-<instanceId>-pending.jsonl`，不支持多个进程共享同一路径。此机制不删除 DSH 会话、SQLite pending_inputs、sources、记忆或审计历史，也不承诺物理安全擦除。

## 何时清理

仅在回放中对读取批次重新等待 `sessions.flush`，完成全部 `event.ingest` 和 `session.cursor` 后，才清理该批用户消息对应的冗余日志记录。读取之后再次 flush，避免初始 flush 后追加的事件被误当作已持久化。单独的 `admitted` 标记不是清理许可。批次 flush 必须明确返回 true；返回 false（没有持久化监听器）会停止该批，不推进游标或压缩。

压缩同步读取当前磁盘文件，不从内存 pending Map 重建。保留每个确认消息的最后一个 admitted 标记以及它后面的捕获记录，原样保留未确认消息的所有记录。同步写入独占临时文件并 flush 后原子替换，再在 POSIX 同步目录；同一 Host 的追加与这一同步操作不会交错。替换前检测文件是否变化只是额外防误用，不是跨进程锁。

## 失败与历史数据

- 写临时文件或替换失败时原文件保留；目录同步失败时文件已替换，但新文件仍含所有未确认输入。错误上抛给既有失败处理，不继续假装清理成功。
- Windows 无可移植目录 fsync，保证范围是进程中断恢复，不承诺系统掉电持久性。
- 旧日志中仅有 admitted、且事件已经位于持久回放游标之前的正文保守保留。成功提交 cursor 后、压缩前中断也可能留下这种冗余正文；此版不回退游标或扫描全部历史来强行回收，因而不是有界磁盘占用保证。
- #9 的 `.corrupt-*` 备份不清理，仍须人工核对。正常启动恢复损坏尾段后，后续压缩可以正常进行。
- 正常异常路径移除临时文件；进程被强制终止可能留下 `.compact-*` 临时文件，它只含准备保留的记录。此版不扫描删除未知旧临时文件。

## 验证范围

测试使用合成内容及故障注入，覆盖持久化链各阶段失败、重复压缩/回放、前后追加、较晚重复捕获、文件变化、临时文件写入/替换/目录同步失败，以及尾段备份与重启。未做真实断电试验，未宣称多写者安全。
